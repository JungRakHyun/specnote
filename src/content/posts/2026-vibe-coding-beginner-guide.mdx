안드레이 카파시(Andrej Karpathy)가 대중화한 <strong>바이브 코딩(Vibe Coding)</strong>으로 비전공자도 하루 만에 웹앱을 띄우는 사례가 많아졌습니다. 하지만 실제로 시작해 보면 <strong>10명 중 7명은 “처음 10분은 신기했는데, 기능 3개째 붙이다가 화면이 깨져서 포기했다”</strong>고 말합니다.

실패 원인은 코딩 지식이 부족해서가 아니라 **순서가 틀렸기 때문**입니다. 비전공자가 첫 웹서비스를 무료로 배포할 때까지 밟아야 할 5단계 절차, 그대로 복사해 쓰는 1페이지 기획서 샘플, 그리고 **바이브 코딩으로 혼자 만들면 위험한 영역**까지 정리했습니다.

## 1. 내 단계에 맞는 바이브 코딩 툴 선택

| 단계 / 구분 | 대표 툴 | 설치 여부 | 장점과 한계 |
| :--- | :--- | :---: | :--- |
| **1단계: 브라우저 올인원** | [Lovable](https://lovable.dev/), [Bolt.new](https://bolt.new/), [v0](https://v0.dev/) | 없음 | 브라우저에서 한국어로 시안·배포까지 10분 완성. **한계:** 크레딧 소모가 빠르고 파일이 많아지면 세밀한 수정이 답답함 |
| **2단계: AI 코드 에디터** | [Cursor](https://www.cursor.com/), [Windsurf](https://windsurf.com/) | PC 설치 | GitHub로 가져온 코드를 파일 단위로 보며 무제한 확장. **한계:** Node.js·Git 기초 설치 10분 필요 |
| **3단계: 터미널 에이전트** | [Claude Code](https://docs.anthropic.com/en/docs/claude-code/overview) | 터미널 | 프로젝트 전체 테스트·리팩토링·자동 배포까지 자율 수행. **한계:** 터미널 로그 기반이라 완전 초보자는 진입 장벽 있음 |

*(4개 주력 도구의 요금 한도와 초과 과금 구조는 [2026 AI 코딩 툴 4종 비교](/posts/2026-ai-coding-tools-guide/)에서 숫자로 비교해 두었습니다.)*

## 2. 실패 확률을 확 줄이는 5단계 실전 로드맵

### STEP 1. 채팅창에 바로 “만들어 줘” 하지 말고 1페이지 PRD부터 쓰기
“카페 예약 사이트 만들어 줘”라고 던지면 AI가 마음대로 기능 20개를 넣다 코드가 꼬입니다. 먼저 아래와 같은 15줄짜리 기획서(`PRD.md`)를 만들어 AI에게 읽히세요.

```markdown
# 프리랜서 견적 계산기 (MVP v1)
- 목적: 클라이언트가 옵션을 고르면 예상 견적과 일정을 즉시 확인하고 PDF/텍스트로 복사
- 핵심 기능 (딱 3개만):
  1) 작업 유형 선택 (랜딩페이지 / 반응형 웹 / 유지보수) + 페이지 수 슬라이더
  2) 선택 항목별 단가 합산 및 부가세(10%) 자동 계산 표
  3) "견적서 텍스트 복사" 버튼 (클립보드 복사 완료 토스트 표시)
- 제외 기능 (v1에서 절대 만들지 말 것): 회원가입, 로그인, 결제, 관리자 페이지
- 디자인: 흰 배경, 남색 포인트(#1D4ED8), 모바일 375px에서 가로 스크롤 없음
```

### STEP 2. 가짜 데이터(Mock)로 화면과 버튼 동작부터 끝내기
로그인·데이터베이스를 첫날부터 붙이면 인증 에러와 CORS 오류에 갇힙니다. 1~2일 차에는 **더미 데이터로 모든 버튼과 모바일 레이아웃이 깔끔하게 동작하는 상태**를 먼저 완성하세요.

### STEP 3. 기능 1개 성공할 때마다 Git 커밋 남기기
AI가 새 기능을 추가하다 멀쩡하던 이전 화면을 망가뜨리는 일은 비일비재합니다. 기능 1개가 눈으로 확인될 때마다 **“방금 추가한 기능 빌드 확인하고 Git 커밋해 줘”** 한 마디만 습관화하면 1초 만에 직전 정상 상태로 돌아갈 수 있습니다.

### STEP 4. DB·로그인이 꼭 필요할 때만 Supabase / Firebase 붙이기
계산기·블로그·소개 페이지는 DB가 아예 필요 없습니다. 사용자 저장 데이터가 꼭 필요한 단계에 이르렀을 때만 [Supabase](https://supabase.com/) 무료 티어를 연결하세요.

### STEP 5. 무료 호스팅 플랫폼 선택 및 공개 배포

| 호스팅 플랫폼 | 무료 티어 특징 | 상업·수익화 사이트 사용 | 추천 대상 |
| :--- | :--- | :--- | :--- |
| **[Cloudflare Pages](https://pages.cloudflare.com/)** | 대역폭 무제한급, 글로벌 CDN 속도 우수 | **가능** | 애드센스 블로그, 정적 웹앱, 계산기 |
| **[GitHub Pages](https://pages.github.com/)** | GitHub 저장소 푸시만으로 자동 배포 | **가능** (정적 사이트) | 포트폴리오, 문서 사이트, Astro 블로그 |
| **[Vercel](https://vercel.com/pricing)** | Next.js·서버 API 라우트 원클릭 배포 | 무료 Hobby는 **비상업용 제한** (수익화 시 Pro 필요) | 풀스택 프로토타입 테스트 |

## 3. 비전공자가 바이브 코딩만으로 출시하면 위험한 3가지

바이브 코딩이 만능은 아닙니다. 아래 3가지가 포함된다면 반드시 개발자 리뷰나 외부 보안 검증을 거쳐야 합니다.
1. **직접 구현한 로그인·결제·포인트 정산:** 클라이언트 코드 조작만으로 금액이 바뀌거나 타인 계정에 접근되는 취약점이 자주 발생합니다. (결제는 토스페이먼츠·Stripe 공식 체크아웃 페이지 위임 권장)
2. **개인정보(주민번호·주소·연락처) 자체 DB 보관:** Supabase RLS(행 수준 보안) 설정을 한 줄만 빠뜨려도 전체 회원 테이블이 브라우저에서 그대로 조회될 수 있습니다.
3. **유료 AI API 키를 프론트엔드에 직접 삽입:** 배포 직후 크롤링 봇이 키를 탈취해 하룻밤 사이 수백 달러 요금이 청구될 수 있습니다.
