“Ollama 깔아서 Qwen 돌리세요”, “로컬 AI 하려면 맥북 사세요” 같은 요약 글은 많지만, 처음 접하는 입장에서는 **애초에 로컬 LLM이 클라우드 AI와 무엇이 다른지, 왜 일반 64GB 램 컴퓨터에서는 느린데 맥북을 추천하는지, 수십 개 오픈 모델 중 무엇이 어떻게 다른지** 연결이 안 되어 막막합니다.

이 글에서는 **① 로컬 LLM의 개념과 4비트 양자화 원리 ② 왜 로컬 LLM에서 맥북(통합 메모리)과 NVIDIA GPU가 갈리는지 ③ 2026년 5대 오픈웨이트 세부 모델(EXAONE 3.5·Qwen3·DeepSeek-R1·Gemma 3·Llama 3.3) 아키텍처·성능 비교 ④ Ollama 설치 직후 필수 트러블슈팅**까지 처음부터 끝까지 인과관계로 정리했습니다.

## 1. 애초에 ‘로컬 LLM’이란 무엇인가? (클라우드 AI와 결정적 차이)

ChatGPT나 Claude 웹에 질문을 치면, 내가 쓴 텍스트와 첨부 파일이 인터넷을 타고 OpenAI·Anthropic의 미국 데이터센터 서버로 날아가 그곳의 초대형 GPU에서 답변을 만든 뒤 화면에 돌려줍니다.

<strong>로컬 LLM(Local Large Language Model)</strong>은 반대로 **공개된 AI 모델의 가중치 파일(오픈웨이트, 보통 `.gguf` 포맷의 4GB~40GB 파일)을 내 컴퓨터 SSD에 직접 다운로드해, 내 PC의 GPU와 메모리에서 스스로 답변을 계산하는 방식**입니다.

| 비교 항목 | 클라우드 AI (ChatGPT · Claude · Gemini) | 로컬 LLM (Ollama · LM Studio) |
| :--- | :--- | :--- |
| **연산 위치** | 외부 기업 데이터센터 서버 | **내 PC의 GPU / 메모리** |
| **인터넷 연결** | 필수 | 모델 다운로드 후 **100% 오프라인 가능** |
| **데이터 보안** | 약관에 따라 외부 서버 전송 (사내 기밀 주의) | **외부 전송 0바이트** (폐쇄망·기밀 문서 안전) |
| **비용 구조** | 월 $20~$200 구독 또는 API 종량제 | **소프트웨어·토큰 비용 0원** (초기 PC 투자·전기료만) |
| **최대 성능** | 초거대 플래그십(수백 B~조 단위) 최고 지능 | 내 PC 메모리 용량(7B~70B)에 비례해 제한됨 |

### 꼭 알아야 할 용어 1개: ‘양자화(Quantization, Q4)’란?
원래 80억 파라미터(`8B`) 모델은 숫자 하나를 16비트 정밀도(`FP16`)로 저장해 **약 16GB** 메모리를 먹습니다. 이걸 소수점 정밀도를 4비트로 압축하는 기술이 <strong>4비트 양자화(<code>Q4_K_M</code>)</strong>입니다. 파일 크기가 **약 5GB로 1/3 이하로 줄어들면서도 실사용 답변 품질은 원본의 95% 안팎을 유지**하기 때문에, 일반 PC와 노트북에서도 AI를 돌릴 수 있게 된 것입니다. (Ollama에서 태그를 지정하지 않으면 기본적으로 이 4비트 양자화 버전이 받아집니다.)

## 2. 로컬 LLM에 대체 왜 ‘맥북(애플 실리콘)’을 추천할까?

가장 많이 나오는 질문입니다. **“내 윈도우 데스크톱에 RAM이 64GB나 있는데 왜 맥북을 추천하나요?”** 답은 **메모리 구조(분리형 vs 통합형)와 LLM의 두 가지 연산 단계**에 있습니다.

### ① 일반 윈도우 PC의 병목: 시스템 RAM ≠ GPU VRAM
일반 PC는 CPU가 쓰는 <strong>시스템 RAM(DDR5, 보통 50~90 GB/s)</strong>과 그래픽카드가 쓰는 <strong>전용 VRAM(GDDR6X/7, 500~1,800 GB/s)</strong>이 물리적으로 갈라져 있습니다. LLM이 답변을 한 글자씩 뽑을 때(**Decode 단계**)는 매 토큰마다 모델 파일 전체를 메모리에서 GPU로 읽어 들여야 하므로 **메모리 대역폭이 곧 답변 속도**입니다.
- 만약 내 그래픽카드 VRAM이 8GB인데 10GB짜리 모델을 올리면, 넘친 2GB가 느린 PCIe 버스를 타고 일반 RAM(CPU)으로 밀려나면서(오프로드) 답변 속도가 **초당 2~4글자로 급락**합니다.
- 즉 윈도우 PC에 RAM이 128GB 있어도 **그래픽카드 VRAM이 8GB면 8GB까지만 빠르게 돌릴 수 있습니다.**

### ② 맥북(애플 실리콘)이 로컬 LLM에서 특이한 강점을 갖는 이유
애플 실리콘(M 시리즈)은 CPU와 GPU가 칩 바로 옆의 고속 메모리를 **복사 없이(Zero-copy) 하나의 풀로 공유하는 통합 메모리(Unified Memory Architecture, UMA)** 구조입니다.
1. **대용량 VRAM을 소비자 가격으로 확보:** NVIDIA에서 48GB~128GB 단일 VRAM을 사려면 수천만 원짜리 워크스테이션 카드나 600W 먹는 듀얼 GPU 조립이 필요합니다. 반면 맥북 프로·맥 스튜디오는 36GB·64GB·128GB 통합 메모리의 약 75%를 GPU가 바로 끌어다 써 **32B~70B 대형 모델을 단독 구동**할 수 있습니다.
2. **저전력·무소음·설치 1분:** NVIDIA 멀티 GPU가 풀로드 시 400~600W 전력을 먹으며 굉음을 내는 동안, 맥북은 30~60W 전력으로 조용히 돌아가고 CUDA 드라이버 충돌 없이 Ollama(Metal 가속)가 바로 붙습니다.

### ③ 반대로 맥북이 NVIDIA보다 불리한 지점 (솔직한 비교)
그렇다고 무조건 맥북이 정답은 아닙니다. LLM 실행은 <strong>Prefill(내가 넣은 긴 프롬프트를 한 번에 읽는 단계, 연산력 의존)</strong>과 <strong>Decode(답변 생성 단계, 대역폭 의존)</strong>로 나뉩니다.
- **24GB 이하 모델(7B~32B)을 최고 속도로 돌리거나, 긴 문서를 빠르게 처리(Prefill)하거나, LoRA 파인튜닝을 할 때:** <strong>NVIDIA GPU(예: 중고 RTX 3090 24GB, 936GB/s)</strong>가 맥북 M4/M5 Pro(273~307GB/s)보다 **답변 속도가 2.5~3배 빠릅니다.**
- **결론:** 24GB 이하 초고속·파인튜닝·최고 가성비는 [RTX 3090 데스크톱](/posts/2026-rtx-3090-local-llm-guide/), 휴대성·무소음·32B~70B 대용량 모델은 [맥북 프로 M4/M5 Pro 또는 맥 스튜디오](/posts/2026-macbook-pro-ai-buying-guide/)로 목적이 완전히 갈립니다.

## 3. 2026년 5대 오픈웨이트 세부 모델 아키텍처 · 성능 비교

로컬 모델은 크기(파라미터)가 같아도 **토크나이저·아키텍처·학습 목적**에 따라 체감 품질이 크게 다릅니다. 2026년 11월 `ollama.com/library` 기준 대표 5개 모델군의 기술적 차이를 비교했습니다.

| 모델군 (개발사) | 아키텍처 특징 | 최대 컨텍스트 | 핵심 강점 영역 | 한국어 품질 | 추천 Ollama 실행 명령 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **EXAONE 3.5** (LG AI연구원) | Dense + GQA, **한·영 50:50 학습**, 102.4K BBPE 토크나이저 | 32K | **한국어 문서 요약·보고서·사내 규정 QA** | **최상** (토큰 분할 효율·뉘앙스 1위) | `ollama run exaone3.5:7.8b` (4.8GB) / `32b` |
| **Qwen3** (Alibaba) | Dense & Sparse MoE, **Thinking 모드 온/오프 전환** | 32K ~ 128K | **코딩(LiveCodeBench/SWE) · 범용 올라운더** | 우수 (100+ 다국어 대규모 학습) | `ollama run qwen3:8b` / `14b` / `32b` |
| **DeepSeek-R1** (DeepSeek) | 순수 RL 기반 **내부 사고(CoT)** + Distill 경량군 | 128K | **수학 · 알고리즘 · 복잡한 버그 단계별 추론** | 양호 (긴 추론 시 간혹 영·중 혼용 주의) | `ollama run deepseek-r1:14b` / `32b` |
| **Gemma 3** (Google) | Dense **네이티브 비전(이미지)**, 5:1 로컬-글로벌 어텐션(KV 캐시 절감) | 128K (1B는 32K) | **스크린샷·영수증·차트 이미지 분석**, 경량 고효율 | 양호 | `ollama run gemma3:12b` (8.1GB) / `27b` |
| **Llama 3.3** (Meta) | 70B Dense + GQA (구 405B급 효율화) | 128K | **에이전트 툴 호출(Tool-use) · 안정적 장문 RAG** | 양호 | `ollama run llama3.3:70b` (43GB, 48GB+ 필수) |

### 내 사용 목적별 첫 모델 선택 기준
1. **한국어 보고서·회의록 요약·이메일 초안 (8~16GB VRAM):** 무조건 **`exaone3.5:7.8b`**부터 돌려보세요. 영어 중심 모델은 한글 한 글자를 2~3토큰으로 쪼개 느리고 어색하지만, EXAONE 3.5는 한국어 50% 비중으로 학습돼 같은 7~8B급에서 문장 완성도와 속도가 확연히 다릅니다.
2. **로컬 코딩 보조·범용 질의응답 (8~24GB VRAM):** **`qwen3:8b` 또는 `qwen3:14b`/`32b`**. 빠른 답이 필요할 때와 깊게 생각해야 할 때를 모두 잘 커버합니다.
3. **이미지·영수증·화면 캡처 분석 (12~16GB VRAM):** **`gemma3:12b`**. 5:1 로컬-글로벌 어텐션 구조 덕분에 긴 문맥을 열어도 KV 캐시 메모리 점유가 적고, `ollama run gemma3:12b "표로 정리해줘" ./capture.png`처럼 바로 이미지를 읽힐 수 있습니다.
4. **수학·로직 검증·어려운 에러 원인 추론 (16~24GB VRAM):** **`deepseek-r1:14b` 또는 `32b`**. 답변 전에 `<think>` 구간에서 스스로 검산 과정을 거치므로 정답률이 높습니다. (단, 사고 토큰을 길게 출력해 체감 응답 시간은 일반 모델보다 깁니다.)

## 4. 실행 툴 선택 (Ollama vs LM Studio) & 설치 직후 트러블슈팅 3가지

| 비교 항목 | [Ollama](https://ollama.com/download) | [LM Studio](https://lmstudio.ai/) |
| :--- | :--- | :--- |
| **실행 방식** | 백그라운드 데몬(`localhost:11434`) + CLI + 기본 데스크톱 채팅 앱 | 전용 GUI 앱 (모델 검색·양자화 비교·TPS 계기판 내장) |
| **적합한 사용자** | VS Code·Cursor·스크립트·[Open WebUI](https://openwebui.com/) 연동 개발자 | 터미널 없이 클릭만으로 모델을 갈아 끼우며 채팅할 입문자 |

설치 자체는 3분이면 끝나지만, 실사용에서 아래 3가지를 모르면 <strong>“생각보다 답변이 너무 느리거나, 긴 문서를 넣으면 앞내용을 잊어버린다”</strong>는 문제로 금방 포기하게 됩니다.

### ① 답변이 초당 2~3글자로 기어갈 때 → GPU 오프로드 확인
모델을 띄운 상태에서 새 터미널을 열어 아래 명령어를 확인하세요.
```bash
ollama ps
```
`PROCESSOR` 열이 **`100% GPU`**가 아니라 `55% CPU / 45% GPU`처럼 갈라져 있다면 모델이 내 VRAM을 넘긴 상태입니다. 한 단계 작은 파라미터 태그(예: `14b → 8b`)로 내려야 정상 속도가 나옵니다.

### ② 긴 문서를 붙여넣으면 앞내용을 까먹을 때 → `num_ctx` 16K 확장
Ollama는 메모리 과점유를 막으려 기본 컨텍스트(`num_ctx`)를 `4096`토큰으로 제한합니다. 16K 컨텍스트 커스텀 모델을 아래처럼 한 번만 만들어 두면 긴 PDF·코드도 문맥이 안 잘립니다.
```bash
echo "FROM exaone3.5:7.8b" > Modelfile
echo "PARAMETER num_ctx 16384" >> Modelfile
ollama create exaone-16k -f Modelfile
ollama run exaone-16k
```

### ③ C드라이브 SSD 용량이 순식간에 찰 때 → 모델 경로 D드라이브 이동
모델 4개만 받아도 40~60GB가 차므로 Windows 사용자는 PowerShell에서 저장 폴더를 미리 옮겨두세요.
```powershell
[System.Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\ollama-models", "User")
```
실행 후 작업 표시줄의 Ollama를 완전히 종료했다가 다시 켜면 새 경로가 적용됩니다.

<Callout type="warning" title="로컬 LLM에 대한 현실적인 기대치 정리">
  24GB VRAM에 32B 모델을 올려도 실시간 웹 리서치나 파일 30개를 동시에 고치는 작업은 클라우드 플래그십([Claude Pro · ChatGPT Plus](/posts/2026-ai-subscription-comparison/))이 여전히 앞섭니다. <strong>사내 보안 문서·개인 코드·오프라인 반복 작업은 로컬 LLM</strong>에 맡기고, 최고난도 설계만 클라우드로 분리하는 하이브리드 전략이 가장 실용적입니다.
</Callout>
