로컬 LLM을 처음 설치한 사람들이 가장 먼저 실망하는 이유는 <strong>“생각보다 답변이 너무 느리거나, 긴 문서를 넣으면 앞내용을 잊어버린다”</strong>는 점입니다. 대부분 PC 성능 자체보다 ① VRAM 용량을 넘는 모델을 받아 CPU로 오프로드됐거나 ② Ollama의 기본 컨텍스트 제한(`4096`)을 그대로 둔 채 썼기 때문에 생기는 문제입니다.

2026년 11월 `ollama.com/library` 공식 태그 기준으로 **내 VRAM에 맞는 정확한 모델 선택표, Ollama vs LM Studio 차이, 그리고 설치 직후 반드시 해두어야 할 트러블슈팅 3가지**를 정리했습니다.

## 1. VRAM 사양별 추천 오픈웨이트 모델 & 실행 명령어 (2026년 11월 기준)

모델 가중치(4비트 양자화 Q4 기준)와 대화 문맥(KV 캐시)을 함께 담으려면 **모델 파일 크기보다 VRAM이 최소 25~30% 넉넉해야** GPU 단독 가속이 유지됩니다.

| 내 VRAM / 통합 메모리 | 대표 하드웨어 | 추천 모델 (Ollama 공식 태그) | 파일 크기(Q4) | 추천 용도 |
| :--- | :--- | :--- | :--- | :--- |
| **8 GB** | RTX 3060 / 4060 / 맥북 16GB | `exaone3.5:7.8b` / `qwen3:8b` | 약 4.8~5.2GB | 한국어 문서 요약, 이메일 초안, 가벼운 코드 보조 |
| **12 ~ 16 GB** | RTX 4060 Ti 16GB / 맥북 24GB | `gemma3:12b` / `deepseek-r1:14b` / `qwen3:14b` | 약 8.1~9.0GB | **이미지 인식(Gemma 3)**, 중급 코딩·추론 |
| **24 GB (실무 기준선)** | **RTX 3090 중고** / 4090 / 맥북 36GB+ | `qwen3:32b` / `deepseek-r1:32b` / `exaone3.5:32b` | 약 19~20GB | 사내 문서 분석, 복잡한 버그 추적, 실전급 로컬 코딩 |
| **48 GB 이상** | RTX 3090 듀얼 / 맥 스튜디오 64GB+ | `llama3.3:70b` | 약 43GB | 클라우드급 대형 모델 오프라인 구동, 장문 RAG |

- **한국어 우선이라면:** LG AI연구원의 `exaone3.5:7.8b`와 알리바바의 `qwen3` 시리즈가 영어 중심 모델 대비 한국어 토크나이저 효율이 높아 같은 크기에서도 문장이 훨씬 자연스럽고 응답도 빠릅니다.

## 2. 소프트웨어 2대장 비교: Ollama vs LM Studio

| 비교 항목 | [Ollama](https://ollama.com/download) | [LM Studio](https://lmstudio.ai/) |
| :--- | :--- | :--- |
| **실행 방식** | 백그라운드 서버(`localhost:11434`) + CLI + 기본 데스크톱 채팅 앱 | 전용 데스크톱 GUI 앱 (모델 검색·슬라이더 튜닝 내장) |
| **강점** | 가벼운 메모리 점유, `ollama launch`·OpenAI 호환 API 연동, Open WebUI 결합 용이 | VRAM 오프로드 레이어 수·초당 토큰(TPS)·양자화(Q4/Q6/Q8)를 눈으로 보며 조절 |
| **추천 대상** | VS Code·Cursor·스크립트·사내 웹서버 연동 개발자 | 터미널 없이 화면에서 모델 비교·채팅을 바로 해보고 싶은 사용자 |

- **브라우저로 ChatGPT처럼 쓰고 싶다면:** Ollama를 실행한 상태에서 Docker로 [Open WebUI](https://openwebui.com/)를 연결하면 `http://localhost:3000`에서 문서 업로드(RAG), 대화 기록 관리, 한국어 메뉴를 그대로 쓸 수 있습니다.

## 3. 설치 직후 꼭 막히는 트러블슈팅 3가지 (복붙 해결)

설치 자체는 공식 설치 파일 클릭 3번으로 끝나지만, 실사용에서 아래 3가지를 모르면 크게 헤맵니다.

### ① 답변이 초당 2~3글자로 너무 느릴 때 → GPU 오프로드 비율 확인
모델이 실행 중일 때 새 터미널을 열어 아래 명령어를 쳐보세요.
```bash
ollama ps
```
출력의 `PROCESSOR` 항목이 **`100% GPU`**가 아니라 `60% CPU / 40% GPU`처럼 쪼개져 있다면 모델이 VRAM을 초과한 상태입니다. 한 단계 작은 태그(예: `14b → 8b`)로 내려야 속도가 정상으로 돌아옵니다.

### ② 긴 문서·코드를 넣으면 앞내용을 잊을 때 → `num_ctx` 확장
Ollama 기본 컨텍스트는 `4096` 토큰(한글 약 2,000~2,500자)에 불과합니다. 긴 문서용 커스텀 모델을 아래처럼 한 번만 만들어 두면 해결됩니다.
```bash
# Modelfile 작성
echo "FROM qwen3:8b" > Modelfile
echo "PARAMETER num_ctx 16384" >> Modelfile

# 16K 컨텍스트 모델 등록 및 실행
ollama create qwen3-16k -f Modelfile
ollama run qwen3-16k
```

### ③ C드라이브 SSD 용량이 순식간에 바닥날 때 → 모델 폴더 D드라이브 이동
모델 3~4개만 받아도 40~60GB가 차기 때문에 Windows 사용자는 PowerShell에서 아래처럼 저장 경로를 D드라이브로 바꿔두는 편이 안전합니다.
```powershell
[System.Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\ollama-models", "User")
```
실행 후 작업 표시줄의 Ollama를 완전히 종료했다가 다시 켜면 이후 다운로드되는 모델이 `D:\ollama-models`에 저장됩니다.

<Callout type="warning" title="로컬 LLM으로도 해결 안 되는 영역 (과대기대 주의)">
  24GB VRAM에 32B 모델을 올려도 최신 웹 정보 검색이나 파일 수십 개를 동시에 리팩토링하는 작업은 클라우드 플래그십 모델이 여전히 한 수 위입니다. <strong>보안 문서·반복 분류·오프라인 코딩은 Ollama</strong>로, 고난도 설계와 최신 리서치는 [클라우드 AI 구독](/posts/2026-ai-subscription-comparison/)으로 나누어 쓰는 구성이 가장 현실적입니다.
