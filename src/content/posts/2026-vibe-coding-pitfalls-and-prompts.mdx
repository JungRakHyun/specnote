바이브 코딩([입문 로드맵 보기](/posts/2026-vibe-coding-beginner-guide/))으로 첫 화면을 띄울 때는 누구나 감탄합니다. 하지만 **파일이 10개를 넘고 기능을 4~5개째 붙이기 시작하면 갑자기 늪에 빠집니다.** 버그 A를 고쳤더니 멀쩡하던 메뉴 B가 깨지고, 에러를 5번 넘게 붙여넣어도 AI가 똑같은 오답을 무한 반복하는 현상입니다.

이 글에서는 <strong>왜 AI가 중반부부터 갑자기 코드를 망가뜨리는지(컨텍스트 오염 원리)</strong>부터 이해한 뒤, **나쁜 vs 좋은 지시 비교, Git 10초 복구 명령어, 그리고 그대로 복사해 쓰는 실전 프롬프트 7종**을 정리했습니다.

## 1. 원리부터 이해하기: 왜 AI는 기능이 늘어나면 갑자기 바보가 될까?

초보자는 “모델 성능이 부족해서”라고 생각하지만, 실제로는 **LLM의 컨텍스트 창이 오염되는 3가지 메커니즘** 때문입니다.

1. **실패 로그 누적(Context Pollution):** 같은 채팅창에서 에러를 4~5번 고치다 보면 대화 기록 안에 **틀린 코드와 임시 우회 패치가 수만 토큰씩 쌓입니다.** AI는 다음 답을 만들 때 그 오염된 기록을 전부 다시 읽으므로 점점 더 꼬인 패치를 덧붙이게 됩니다.
2. **단일 파일 비대화(Attention 분산):** 한 파일이 400~800줄을 넘어가면 AI가 파일 중간의 상태 변수나 CSS 클래스를 놓치고 중복 함수를 새로 만들어 기존 기능을 덮어씁니다.
3. **범위 미지정(추측 리팩토링):** “안 눌려요, 고쳐주세요”처럼 범위 없이 던지면 AI가 에러와 무관한 설정 파일이나 패키지 버전까지 건드려 연쇄 장애(회귀 버그)를 일으킵니다.

## 2. 망가지는 지시 vs 한 번에 통하는 지시 (Before / After)

| 상황 | ❌ 코드를 망가뜨리는 지시 | ✅ 한 번에 해결되는 지시 (범위·근거 고정) |
| :--- | :--- | :--- |
| 기능 추가 | “로그인, 마이페이지, 다크모드 다 만들어 줘” | “다크모드 토글만 먼저 구현해 줘. 코드 수정 전에 건드릴 파일 목록과 계획을 5줄로 먼저 보여줘.” |
| 버그 수정 | “결제 버튼이 안 눌려요. 고쳐주세요.” | “결제 버튼 클릭 시 콘솔에 `TypeError: Cannot read properties of undefined`가 뜸. `CheckoutButton.tsx`만 보고 원인 2가지를 먼저 설명해 줘.” |
| 디자인 개선 | “더 예쁘고 트렌디하게 바꿔줘.” | “기존 로직 수정 금지. 그라데이션·이모지 제거, 배경 `#FFFFFF`·보조 `#F8FAFC`·포인트 `#1D4ED8` 1색, 모바일 375px 가로 스크롤 없음 조건으로 UI만 정리해 줘.” |

## 3. 초보자가 가장 자주 겪는 4대 사고 & 10초 복구법

1. **3번 연속 에러 수정 실패 → 즉시 원복 + 새 채팅창 열기:** 오염된 대화를 버리고 직전 정상 코드로 되돌린 뒤 새 세션에서 시작하는 게 10배 빠릅니다.
```bash
# 커밋하지 않은 망가진 수정사항만 직전 정상 상태로 일괄 취소
git restore .

# 새로 생긴 찌꺼기 파일(Untracked) 확인
git status
```
2. **공개 GitHub 저장소에 `.env` 파일 업로드:** 프로젝트 첫날 루트의 `.gitignore`에 아래 4줄이 들어있는지 반드시 확인하세요.
```text
.env
.env.local
.env.*.local
node_modules/
```
3. **프론트엔드 환경변수 접두사 착각:** Vite의 `VITE_*`, Next.js의 `NEXT_PUBLIC_*`, Astro의 `PUBLIC_*` 변수는 **빌드 시 브라우저 자바스크립트 파일에 평문으로 박힙니다.** 유료 OpenAI·Claude·결제 시크릿 키는 절대 이 접두사를 쓰지 말고 서버(API Route, Cloudflare Workers, Supabase Edge Functions) 쪽에서만 호출하세요.
4. **400줄 넘게 커진 컴포넌트 방치:** 기능이 잘 돌아갈 때 미리 컴포넌트·유틸 파일로 쪼개두어야 다음 기능 추가 시 회귀 버그를 막습니다.

## 4. 바로 복사해서 쓰는 실전 프롬프트 7종 (효과 원리 포함)

### ① 프로젝트 규칙 고정 — 첫날 1회 (매 턴 반복 설명 제거)
```text
이 프로젝트의 기술 스택, 폴더 구조, 빌드 명령을 요약한 CLAUDE.md(또는 PROJECT_RULES.md)를 만들어 줘.
앞으로 모든 작업에서 1) 한 번에 1개 기능만 수정 2) 요청하지 않은 패키지 추가 금지 3) 모바일(375px) 레이아웃 깨짐 방지 원칙을 지켜 줘.
```

### ② 코드 수정 전 계획 승인 — 꼬임 방지 1순위 (추측 수정 차단)
```text
지금 바로 코드를 수정하지 말고, [원하는 기능]을 구현하기 위해
1) 수정·생성할 파일 목록 2) 변경 방식 3) 기존 기능에 미칠 부작용을 5줄 이내로 먼저 설명해 줘. 내가 승인하면 그때 코드를 작성해 줘.
```

### ③ 에러 무한 루프 탈출 — 반드시 새 채팅창에서 실행 (가설 검증 강제)
```text
아래 에러 로그가 발생했어. 바로 코드를 덮어쓰지 말고,
먼저 발생 가능한 원인 3가지를 추론한 뒤 가장 확실한 원인 1개를 골라 최소 범위만 수정해 줘.
[여기에 터미널 또는 브라우저 콘솔 에러 로그 전체 붙여넣기]
```

### ④ ‘AI 템플릿 티’ 지우기 — 로직 보호 + 금지 스타일 명시
```text
기존 기능 로직과 데이터 흐름은 절대 건드리지 말고 UI 스타일만 정리해 줘.
조건: 1) 과한 그라데이션·그림자·장식용 이모지 제거 2) 배경 #FFFFFF / 보조 #F8FAFC / 포인트 #1D4ED8 1색 제한 3) 모바일 375px에서 가로 스크롤 없음.
```

### ⑤ 기능 1개 완료 후 빌드 검증 + Git 체크포인트 저장
```text
방금 추가한 기능이 프로덕션 빌드(npm run build) 오류 없이 통과하는지 확인하고,
변경 파일 요약과 함께 되돌리기 쉬운 단위로 git commit을 생성해 줘.
```

### ⑥ 배포 직전 보안·키 노출 셀프 감사 (다른 모델로 교차 검증 권장)
```text
배포 직전 보안 점검을 표로 보고해 줘.
1) 프론트엔드 코드나 Git 추적 파일에 API 키(sk-, AIza 등)·비밀번호가 노출된 곳이 있는지
2) .gitignore에 .env 및 .env.local이 포함되어 있는지
3) 사용자 입력값 검증이나 인증 체크가 빠진 서버 API·DB 권한(RLS)이 있는지 확인해 줘.
```

### ⑦ 비대해진 파일 안전하게 분리하기 (400줄 초과 시)
```text
[파일명]이 400줄을 넘어 유지보수가 어려워졌어.
화면과 동작은 100% 동일하게 유지하면서 재사용 가능한 컴포넌트·유틸 파일로 분리하고, 분리 직후 빌드 테스트까지 통과시켜 줘.
```

<Callout type="warning" title="실수로 GitHub에 API 키를 올렸다면 커밋 삭제보다 '폐기'가 먼저입니다">
  커밋을 덮어쓰거나 삭제해도 Git 히스토리와 외부 스캐너 봇은 보통 수 분 안에 노출된 키를 수집합니다. <code>.env</code>를 실수로 푸시했다면 코드 수정보다 <strong>해당 서비스 대시보드에서 기존 API 키를 즉시 폐기(Revoke)하고 새 키를 재발급</strong>하는 것이 최우선입니다.
</Callout>

## 5. 모델별 디버깅 특성 & 안정적인 작업 리듬

같은 디버깅 프롬프트를 넣어도 어떤 모델에 던지느냐에 따라 해결 패턴이 다릅니다. 한 모델이 같은 버그에서 두 번 이상 헛발질할 때는 **다른 모델로 교차 검증**하는 것이 가장 빠른 탈출구입니다.

- **Claude (Sonnet / Opus · Claude Code):** 파일 간 의존성과 타입 에러 원인을 차분히 추적하는 능력이 강해, 빌드 오류나 리팩토링 회귀 버그 해결에 가장 안정적입니다.
- **GPT 추론 모델 (ChatGPT / Cursor):** 복잡한 비즈니스 로직·알고리즘·정규식 오류처럼 단계적 검증이 필요한 버그에서 다른 시각의 대안을 잘 제시합니다.
- **권장 작업 리듬:** `1페이지 PRD → 계획 5줄 승인 → 기능 1개만 구현 → 빌드·모바일 375px 확인 → Git 커밋 → 새 세션(/clear)` 6단계를 반복하면 비전공자도 파일 30~50개 규모의 웹서비스를 무너지지 않고 유지보수할 수 있습니다. 도구별 상세 비교는 [2026 AI 코딩 툴 심층 비교](/posts/2026-ai-coding-tools-guide/)를 참고하세요.
