바이브 코딩([입문 로드맵 보기](/posts/2026-vibe-coding-beginner-guide/))으로 첫 화면을 띄우는 데는 10분이면 충분합니다. 진짜 벽은 **기능을 4~5개째 붙일 때** 찾아옵니다. 버그 하나를 고쳤더니 멀쩡하던 메뉴가 깨지고, 에러를 5번 넘게 붙여넣어도 AI가 똑같은 오답을 반복하는 ‘무한 루프’에 갇히는 패턴입니다.

실제 프로젝트에서 코드 꼬임을 막고 품질을 끌어올리는 **나쁜 지시 vs 좋은 지시 비교, 긴급 Git 복구 명령어, 그리고 그대로 복사해 쓰는 실전 프롬프트 7종**을 정리했습니다.

## 1. 에러가 터지는 지시 vs 한 번에 통하는 지시 (Before / After)

| 상황 | ❌ 망가지는 지시 (추측 유발) | ✅ 한 번에 해결되는 지시 (범위 고정) |
| :--- | :--- | :--- |
| 기능 추가 | “로그인, 마이페이지, 다크모드 한꺼번에 만들어 줘” | “다크모드 토글만 먼저 구현해 줘. 수정 전 건드릴 파일 목록을 먼저 알려줘.” |
| 버그 수정 | “결제 버튼이 안 눌려요. 고쳐주세요.” | “결제 버튼 클릭 시 콘솔에 `TypeError: Cannot read properties of undefined`가 뜸. `CheckoutButton.tsx`만 보고 원인 2가지를 먼저 설명해 줘.” |
| 디자인 수정 | “더 예쁘고 세련되게 바꿔줘.” | “배경 그라데이션·이모지 제거, 본문 글자크기 16px·행간 1.7, 포인트 색 `#1D4ED8` 1종만 써서 UI만 리팩토링해 줘. 로직 변경 금지.” |

## 2. 초보자가 가장 자주 겪는 4대 사고 & 10초 복구법

1. **같은 채팅창에서 에러 3회 이상 반복:** 대화가 길어질수록 실패한 패치 기록이 AI 문맥을 오염시킵니다. **3번 실패하면 즉시 새 채팅을 열고**, 아래 명령으로 직전 정상 코드로 되돌린 뒤 다시 시작하세요.
```bash
# 커밋하지 않은 망가진 수정사항만 직전 정상 상태로 일괄 취소
git restore .
# 새로 생긴 찌꺼기 파일까지 함께 확인하려면
git status
```
2. **공개 GitHub 저장소에 `.env` 키 파일 업로드:** 프로젝트 생성 직후 루트의 `.gitignore`에 아래 4줄이 들어있는지 반드시 확인해야 합니다.
```text
.env
.env.local
.env.*.local
node_modules/
```
3. **프론트엔드 코드에 비밀 키 직접 삽입:** `VITE_`, `NEXT_PUBLIC_` 접두사가 붙은 환경변수는 **브라우저에 그대로 노출**됩니다. 유료 AI API 키나 결제 시크릿 키는 반드시 서버(API Route, Cloudflare Workers, Supabase Edge Functions) 쪽에서만 호출하세요.
4. **400줄 넘게 커진 단일 파일:** 한 파일이 500~1,000줄로 불어나면 AI가 앞부분 코드를 놓쳐 회귀 버그를 만듭니다. 300~400줄을 넘기기 전에 컴포넌트 단위로 쪼개두어야 합니다.

## 3. 바로 복사해서 쓰는 바이브 코딩 실전 프롬프트 7종

### ① 프로젝트 규칙 고정 (첫날 1회 실행)
```text
이 프로젝트의 기술 스택, 폴더 구조, 빌드 명령을 요약한 CLAUDE.md(또는 PROJECT_RULES.md)를 만들어 줘.
앞으로 모든 작업에서 1) 한 번에 1개 기능만 수정 2) 요청하지 않은 패키지 추가 금지 3) 모바일(375px) 레이아웃 깨짐 방지 원칙을 지켜 줘.
```

### ② 코드 수정 전 계획 승인 (코드 꼬임 방지 1순위)
```text
지금 바로 코드를 수정하지 말고, [원하는 기능]을 구현하기 위해
1) 수정·생성할 파일 목록 2) 변경 방식 3) 기존 기능에 미칠 부작용을 5줄 이내로 먼저 설명해 줘. 내가 승인하면 그때 코드를 작성해 줘.
```

### ③ 에러 무한 루프 탈출 (새 채팅창에서 실행)
```text
아래 에러 로그가 발생했어. 바로 코드를 덮어쓰지 말고,
먼저 발생 가능한 원인 3가지를 추론한 뒤 가장 확실한 원인 1개를 골라 최소 범위만 수정해 줘.
[여기에 터미널 또는 브라우저 콘솔 에러 로그 전체 붙여넣기]
```

### ④ ‘AI 템플릿 티’ 지우기 (UI 정리 전용)
```text
기존 기능 로직과 데이터 흐름은 절대 건드리지 말고 UI 스타일만 정리해 줘.
조건: 1) 과한 그라데이션·그림자·장식용 이모지 제거 2) 배경 #FFFFFF / 보조 #F8FAFC / 포인트 #1D4ED8 1색 제한 3) 모바일 375px에서 가로 스크롤 없음.
```

### ⑤ 기능 1개 완료 후 검증 + Git 저장점 만들기
```text
방금 추가한 기능이 프로덕션 빌드(npm run build) 오류 없이 통과하는지 확인하고,
변경 파일 요약과 함께 되돌리기 쉬운 단위로 git commit을 생성해 줘.
```

### ⑥ 배포 직전 보안·키 노출 셀프 감사 (공개 전 필수)
```text
배포 직전 보안 점검을 표로 보고해 줘.
1) 프론트엔드 코드나 Git 추적 파일에 API 키(sk-, AIza 등)·비밀번호가 노출된 곳이 있는지
2) .gitignore에 .env 및 .env.local이 포함되어 있는지
3) 사용자 입력값 검증이나 인증 체크가 빠진 서버 API·DB 권한(RLS)이 있는지 확인해 줘.
```

### ⑦ 비대해진 파일 안전하게 분리하기
```text
[파일명]이 400줄을 넘어 유지보수가 어려워졌어.
화면과 동작은 100% 동일하게 유지하면서 재사용 가능한 컴포넌트·유틸 파일로 분리하고, 분리 직후 빌드 테스트까지 통과시켜 줘.
```

<Callout type="warning" title="실수로 GitHub에 API 키를 올렸다면?">
  커밋을 지우거나 덮어써도 Git 히스토리에 키가 남고, 봇은 보통 몇 분 안에 노출된 키를 수집합니다. <code>.env</code>를 실수로 푸시했다면 코드 수정보다 <strong>해당 서비스 대시보드에서 기존 API 키를 즉시 폐기(Revoke)하고 새 키를 재발급</strong>하는 것이 최우선입니다.
</Callout>
